# Qwant Server — серверная часть

Серверная часть клиент-серверного решения по кейсу
**«Мобильное приложение для водителей дизельной техники»**
(см. фото-ТЗ в корне репозитория и `../AGENTS.md`).

Стек: **Kotlin + Ktor 3.6 + sqlite3** (JDBC-драйвер `org.xerial:sqlite-jdbc`).
Данные отдаются в JSON.

---

## 1. Требования

- **JDK 21+** (проект собирается таргетом 21, toolchain подтянется автоматически).
- Интернет при первой сборке (скачивание зависимостей Ktor).

## 2. Запуск

```bash
# из корня репозитория Qwant2
./gradlew -p server run
```

или из каталога `server/`:

```bash
./run.sh
```

По умолчанию сервер слушает **`http://0.0.0.0:8080`**.
Для Android-эмулятора хост-машина доступна как **`http://10.0.2.2:8080`**.

> Если порт 8080 занят: `PORT=8090 ./gradlew -p server run`.

Собрать запускаемый дистрибутив (скрипт в `server/build/install/qwant-server/bin/`):

```bash
./gradlew -p server installDist
```

Прогнать тесты:

```bash
./gradlew -p server test
```

## 3. Настройка (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `QWANT_DB` | `:memory:` | Путь к файлу БД sqlite3. По умолчанию — **образная база в памяти**, заполняется образцами при каждом старте. Укажите путь, чтобы сохранять данные между запусками. |
| `QWANT_ELECTROLYZERS` | `150` | Количество электролизёров в **корпусе по умолчанию** (№4): **100 или 150**. У второго корпуса (№3) число дополняет пару «100/150» |

Пример с файловой БД и 100 электролизёрами:

```bash
QWANT_DB=./qwant.db QWANT_ELECTROLYZERS=100 ./gradlew -p server run
```

### Модель данных (sqlite3)

- `equipment` — дизельная техника (`MRG` — раздачи глинозёма, `MPK` — пробойки корки), наработка в **моточасах**;
- `drivers` — водители (каждый закреплён за техникой);
- `electrolyzers` — электролизёры: `building`, `row` (ряд), `position`, `half` (`A`/`B`), `series`, `status`; в образцовой базе **два корпуса** (№4 и №3), нумерация в каждом начинается с 1;
- `zones` — **опасные зоны** (`DANGER`) и **тупики** (`DEAD_END`) на схеме корпуса (координаты 0..1), у каждого корпуса свои;
- `gates` — ворота корпуса (дистанционное открытие); в образцовой базе это **единственный вход** в каждый корпус — `x < 0.5` задаёт вход слева, иначе справа (у корпуса №4 вход слева, у №3 — справа);
- `deviation_tags` — быстрые теги отклонений (выбор без ввода текста);
- `orders` — заявки;
- `users` — учётные записи (`login`, `password_hash`, `role` = `DISPATCHER`/`DRIVER`, привязка к `driver_id`);
- `sessions` — активные токены авторизации (`token`, `user_id`, `created_at`).

### Пользователи (образцовые, при наполнении БД)

| Логин | Пароль | Роль | Водитель |
|---|---|---|---|
| `dispatcher` | `1234` | Диспетчер | — |
| `ivanov` | `1234` | Водитель | Иванов А. (id 1) |
| `petrov` | `1234` | Водитель | Петров С. (id 2) |
| `sidorov` | `1234` | Водитель | Сидоров В. (id 3) |
| `kuznetsov` | `1234` | Водитель | Кузнецов Д. (id 4) |

Пароли хранятся как **SHA-256 с солью** (`password_hash`), в открытом виде не сохраняются.

### Корпуса и раскладка электролизёров

В образцовой базе **два корпуса** (`GET /api/buildings`): клиент открывает схему
выбранного корпуса (`GET /api/scheme?building=…`).

| Корпус | Всего | Ряды | В ряду | Половина | Вход |
|---|---|---|---|---|---|
| №4 (по умолчанию) | 150 | 5 | 30 | 15 | слева |
| №3 | 100 | 5 | 20 | 10 | справа |

Число электролизёров корпуса №4 задаёт `QWANT_ELECTROLYZERS`; корпус №3 получает
дополняющее число (пара «100 и 150», как в ТЗ). Электролизёры расположены
**параллельными рядами и делены пополам**: `rows = 5`, `perRow = count / 5`,
`halfSize = perRow / 2`. Половина `A` — первая половина ряда, `B` — вторая.

### Бизнес-правила

- **Авторизация по логину/паролю.** `POST /api/auth/login` выдаёт токен; далее запросы
  передают его в заголовке `X-Auth-Token`. Роль (`DISPATCHER`/`DRIVER`) хранится в учётке.
- **Разграничение ролей на сервере:**
  - `POST /api/orders` (постановка заявки) — **только диспетчер** (иначе `403`);
  - `/accept` и `/complete` — **только водитель**, `driverId` берётся из токена (не из тела);
  - открытие/закрытие ворот — любой авторизованный пользователь (без токена `401`);
  - `GET`-эндпоинты чтения — открыты.
- **Два действия водителя:** получить заявку → «Взять в работу» (`/accept`) → «Выполнено» (`/complete`).
- **Светофор срочности** (только для заявок `PODSYPKA` в статусе `ACCEPTED`):
  🟢 зелёный сразу, 🟠 оранжевый с 10 мин, 🔴 красный с 15 мин. Поле `urgency` в JSON заявки.
- **Моточасы:** при завершении заявки с `motohoursDelta` наработка начисляется на технику исполнителя.
- **Заявка на ремонт из кабины** — тип `REMONT`, `isRepair = true`.

## 5. REST API

Базовый префикс — `/api`. Тело запросов/ответов — JSON.
Защищённые эндпоинты требуют заголовок **`X-Auth-Token: <token>`** (из `/api/auth/login`).

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| GET | `/api/health` | — | Проверка доступности |
| POST | `/api/auth/login` | — | Вход `{ "login": "…", "password": "…" }` → `{ token, user }` |
| POST | `/api/auth/logout` | вход | Выход (аннулирует текущий токен) |
| GET | `/api/auth/me` | вход | Текущий пользователь по токену |
| GET | `/api/config` | — | Параметры схемы (корпус по умолчанию, ряды, размер половины, число электролизёров, список корпусов) |
| GET | `/api/equipment` | — | Список техники с моточасами |
| GET | `/api/equipment/{id}` | — | Техника по id |
| POST | `/api/equipment/{id}/motohours` | диспетчер | Начислить моточасы `{ "delta": 2.5 }` |
| GET | `/api/drivers` | — | Водители (с закреплённой техникой) |
| GET | `/api/buildings` | — | Корпуса цеха: идентификатор, название и раскладка (для выбора корпуса на схеме) |
| GET | `/api/electrolyzers?building=4` | — | Электролизёры (всех корпусов или указанного) |
| GET | `/api/scheme?building=4` | — | Схема корпуса: электролизёры + зоны + ворота (`404`, если корпуса нет) |
| GET | `/api/gates` | — | Ворота |
| POST | `/api/gates/{id}/open` | вход | **Дистанционно открыть** ворота |
| POST | `/api/gates/{id}/close` | вход | Закрыть ворота |
| GET | `/api/tags` | — | Быстрые теги отклонений |
| GET | `/api/stats` | — | Статистика наработки (моточасы по технике/типам, счётчики заявок) |
| GET | `/api/orders?status=&driverId=&isRepair=` | — | Список заявок с фильтрами |
| GET | `/api/orders/{id}` | — | Заявка по id |
| POST | `/api/orders` | диспетчер | Создать заявку |
| POST | `/api/orders/{id}/accept` | водитель | **«Взять в работу»** (исполнитель — владелец токена) |
| POST | `/api/orders/{id}/complete` | водитель | **«Выполнено»** `{ "deviationTagId": 1, "comment": "…", "motohoursDelta": 2.0 }` |

### Примеры

```bash
# вход диспетчера -> токен
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"dispatcher","password":"1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# новая заявка у диспетчера (нужен токен диспетчера)
curl -X POST localhost:8080/api/orders \
  -H "X-Auth-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"type":"PODSYPKA","electrolyzerId":125}'

# вход водителя -> токен водителя, он же становится исполнителем
DTOKEN=$(curl -s -X POST localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"ivanov","password":"1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# водитель берёт в работу
curl -X POST localhost:8080/api/orders/1/accept -H "X-Auth-Token: $DTOKEN"

# водитель завершает
curl -X POST localhost:8080/api/orders/1/complete \
  -H "X-Auth-Token: $DTOKEN" -H 'Content-Type: application/json' \
  -d '{"deviationTagId":1,"comment":"Засор лотка","motohoursDelta":1.5}'

# дистанционное открытие ворот (любой авторизованный)
curl -X POST localhost:8080/api/gates/1/open -H "X-Auth-Token: $TOKEN"

# статистика наработки
curl localhost:8080/api/stats
```

### Поля заявки (фрагмент ответа)

```json
{
  "id": 2,
  "type": "PODSYPKA",
  "status": "ACCEPTED",
  "electrolyzerNumber": 42,
  "building": "4",
  "row": 2, "position": 12, "half": "A",
  "driverId": 1, "driverName": "Иванов А.",
  "elapsedMinutes": 12,
  "urgency": "ORANGE",
  "createdAt": "...", "acceptedAt": "...", "completedAt": null
}
```

## 6. Принципы работы

1. При старте `Db` открывает соединение sqlite3, создаёт схему и, если база пуста,
   **наполняет её образцами**: техника, водители, электролизёры **двух корпусов**,
   зоны, ворота, теги, несколько заявок в разных статусах и **учётные записи**
   (см. таблицу выше).
2. Каждый HTTP-запрос читает/меняет состояние через DAO (`Db`). Заявка меняет статус
   по мере действий водителя; «светофор» вычисляется на лету по времени принятия;
   схема корпуса строится по `building` (раскладка, зоны и ворота — свои у каждого).
3. Защищённые операции проверяют **токен** (`X-Auth-Token`) и **роль**: постановка
   заявок — диспетчер, принятие/завершение — водитель (исполнитель берётся из токена).
4. Мобильный клиент (Android) входит по логину/паролю, хранит токен в сессии и
   опрашивает эндпоинты: получает заявки, схему корпуса, статистику; отправляет
   действия «Взять в работу»/«Выполнено» и открытие ворот.
