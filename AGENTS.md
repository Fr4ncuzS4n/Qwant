# AGENTS.md — Qwant

Инструкции для ИИ-агентов и разработчиков, работающих в этом репозитории.

> **Важно про название.** Каталог называется `Qwant2`, `rootProject.name = "Qwant"`,
> но к поисковику Qwant это отношения не имеет. `Qwant` — это **заглушка/опечатка**
> в шаблоне проекта. Реальное назначение приложения описано ниже (см. «Домен и ТЗ»).
> Переименование проекта в `Qwant` пока не делалось осознанно — не «исправляйте»
> название и package без явной просьбы пользователя.

---

## 1. Что это за проект

Android-приложение (планшет) для **водителей дизельной техники** электролизного
производства алюминия. Проект создан по кейсу
**«Мобильное приложение для водителей дизельной техники»** — это студенческий /
хакатонный кейс (клиент-серверное решение).

Требования кейса зафиксированы **только в двух JPG-фото спецификации в корне
репозитория** (см. п. 3). Текстовой копии ТЗ в репозитории нет — не считайте
эти JPG мусором и не удаляйте.

По состоянию на текущий момент:
- **Серверная часть реализована** в каталоге `server/` (Kotlin + Ktor + sqlite3,
  REST API со всем функционалом ТЗ — см. п. 5 и `server/README.md`).
- **Android-часть реализована** как клиент к этому серверу: два личных кабинета
  (водитель и диспетчер), заявки, схема корпуса с опасными зонами/тупиками,
  дистанционное управление воротами и статистика наработки (см. п. 6).

## 2. Домен и ТЗ (выжимка из фото-спецификации)

**Назначение:** автоматизировать работу водителей с заявками (обработка
электролизёров), минимизировать действия водителя — **всего 2 основных действия**.

**Сценарий водителя:**
1. **Получение и принятие:** на планшете появляется крупное уведомление вида
   «Новая заявка: корпус 4, электролизер №125. Тип: обработка …». Водитель жмёт
   одну кнопку **«Взять в работу»** — статус заявки меняется, диспетчер видит
   исполнителя.
2. **Завершение:** по окончании работы водитель жмёт **«Выполнено»**.

При отклонениях (например, неисправность узла электролизёра) водитель выбирает
**быстрый тег из списка** — без ручного ввода текста.

**Обязательный минимальный функционал:**
- личный кабинет **водителя**;
- личный кабинет **диспетчера**;
- база данных **статистики наработки оборудования** (в моточасах).

**Функционал из описания задания:**
- онлайн-заявки с указанием **электролизёра на схеме корпуса**;
- отметка о выполнении и **контроль времени исполнения**;
- статистика наработки оборудования **в моточасах**;
- подача заявки на ремонт из кабины с указанием места на схеме;
- отметка **опасных зон и тупиков** на схеме корпуса;
- дистанционное открытие ворот при выезде в корпус.

**Дополнительное требование — индикация срочности («светофор»)** для заявок
по МРГ (подсыпка):
- сразу после принятия заявки — 🟢 зелёный;
- через **10 минут** — 🟠 оранжевый;
- через **15 минут** — 🔴 красный.

**Техника (предметная область):**
- **МРГ** — машина раздачи глинозёма (транспортировка/раздача глинозёма,
  бункер + выгрузной лоток);
- **МПК** — машина пробойки корки (разрушение криолит-глинозёмной корки,
  электролит ~960 °C, спец. стрела с пробойным инструментом).

**Архитектура решения (из ТЗ):** клиент-серверное приложение — Android-клиент
+ сервер. Диспетчер и водитель синхронизируются по статусам заявок. Итоговый
результат: APK + документация + открытый репозиторий.

**Критерии оценки (для понимания приоритетов):** соблюдение дополнительных
требований (0–30), соответствие теме (0–10), лаконичность кода (0–10),
рациональность решения (0–10), оригинальность идеи (0–10), законченность работы
и удобство интерфейса (0–10), наличие открытого репозитория с исходниками и
описанием (0–20).

```kotlin

    compileSdk { version = release(37) }

```

**Команды:**

Манифест запрашивает `INTERNET` и разрешает cleartext HTTP к dev-серверу.

## 4. Серверная часть (`server/`) — РЕАЛИЗОВАНО

Отдельный Gradle-проект (не модуль Android-сборки), запускается независимо:

```
server/
├── build.gradle.kts      # Kotlin JVM 2.3.21, Ktor 3.6.0, sqlite-jdbc, logback
├── settings.gradle.kts   # rootProject.name = "qwant-server"
├── run.sh                # ./run.sh  ==  ../gradlew run
├── README.md             # запуск + полное описание REST API
└── src/
    ├── main/kotlin/com/example/qwant/server/
    │   ├── Main.kt       # точка входа Ktor, плагины и все маршруты /api/* (вкл. /api/auth/*)
    │   ├── Database.kt   # sqlite3: схема, образцовые данные, DAO, пользователи и сессии
    │   ├── Models.kt     # доменные модели и константы (типы, статусы, зоны, роли)
    │   └── Urgency.kt    # правила «светофора» (10/15 мин)
    └── test/kotlin/…      # JUnit5: UrgencyRulesTest (9) + DatabaseTest (15) + AuthTest (16)
```

**Стек:** Kotlin 2.3.21, Ktor 3.6.0 (Netty, ContentNegotiation+Gson, CORS,
StatusPages, CallLogging), `org.xerial:sqlite-jdbc`, logback. JDK 21.

**Команды (из корня репозитория):**
```bash
./gradlew -p server run        # запустить сервер (http://0.0.0.0:8080)
./gradlew -p server test       # 40 unit-тестов
./gradlew -p server installDist
```
Переменные: `PORT` (8080), `QWANT_DB` (`:memory:` — образная БД в памяти),
`QWANT_ELECTROLYZERS` (`150`; допустимо `100` — число электролизёров корпуса по
умолчанию). **Порт 8080 по умолчанию**;
адрес для Android-эмулятора — `http://10.0.2.2:8080`.

**Авторизация и роли (добавлено):**
- Таблицы `users` (логин, SHA-256-хэш пароля, роль, привязка к водителю) и `sessions` (токены).
- Эндпоинты: `POST /api/auth/login` → `{ token, user }`, `POST /api/auth/logout`, `GET /api/auth/me`.
- Токен передаётся в заголовке **`X-Auth-Token`**; пользователь резолвится `currentUser()`.
- Образцовые учётки (пароль `1234`): `dispatcher` (DISPATCHER) и
  `ivanov|petrov|sidorov|kuznetsov` (DRIVER, водители 1..4).
- Ролевые ограничения: `POST /api/orders` — только диспетчер (`403`); `accept`/`complete`
  — только водитель, `driverId` берётся **из токена** (тело его больше не содержит);
  ворота open/close — любой авторизованный (`401` без токена). `GET` — открыты.

**Ключевые правила реализации (не ломать при доработках):**
- БД — **sqlite3**; по умолчанию образная база в памяти, наполняется при старте.
- Электролизёры: `rows = 2` — **две линии по обе стороны центральной дороги**
  корпуса, `perRow = count / 2`, **линия делится пополам** (`half` = `A`/`B`);
  в образцовой БД **четыре корпуса** — №4 (по умолчанию), №3, №2 и №1, у всех
  **одинаковое** число электролизёров, задаёт `QWANT_ELECTROLYZERS`
  (100 или 150); нумерация электролизёров в каждом корпусе начинается с 1
  (таблицу см. в `server/README.md`).
- **Корпуса:** `GET /api/buildings` — список корпусов с раскладкой; `GET /api/scheme?building=…`
  собирает схему выбранного корпуса (`404`, если корпуса нет; по умолчанию — `Db.DEFAULT_BUILDING` = «4»).
- «Светофор» — только для заявок `PODSYPKA` в статусе `ACCEPTED`:
  🟢 < 10 мин, 🟠 10–14 мин, 🔴 ≥ 15 мин (`Urgency.kt`).
- При завершении заявки с `motohoursDelta` моточасы начисляются на технику исполнителя.
- В образцовой БД у **каждого корпуса один вход** (одни ворота); его координата `x < 0.5`
  задаёт вход слева, иначе справа (клиент рисует разрыв стены на этой стороне);
  у корпуса №4 вход слева, у №3 — справа.
- Полный перечень эндпоинтов — в `server/README.md` (раздел 5). При добавлении
  маршрутов обновляйте и README, и этот файл.

## 5. Структура и текущее состояние Android-части

Единственный модуль — `:app`, package `com.example.qwant`, `applicationId = "com.example.qwant"`.

```
app/src/main/
├── AndroidManifest.xml                 # 1 Activity, INTERNET, usesCleartextTraffic (dev-сервер по HTTP)
├── java/com/example/qwant/
│   ├── MainActivity.kt                 # QwantTheme { QwantApp() } — NavHost, старт по сессии, guard по ролям
│   ├── data/
│   │   ├── Models.kt                   # @Serializable DTO сервера + константы (Role/OrderType/OrderStatus/ZoneKind/Urgency) + Login*
│   │   ├── QwantApi.kt                 # Ktor-клиент: BASE_URL из ServerConfig, токен X-Auth-Token, все /api/* + /api/auth/*
│   │   ├── ServerConfig.kt             # адрес сервера (дефолт 10.0.2.2:8080), настройка в UI + SharedPreferences
│   │   └── SessionStore.kt             # SharedPreferences: сессия (токен + пользователь + роль)
│   ├── screens/
│   │   ├── AuthScreen.kt / AuthViewModel.kt   # ВХОД по логину/паролю (стартовый экран)
│   │   ├── DeveloperScreen.kt / DeveloperViewModel.kt  # «Для разработчика»: адрес сервера + проверка связи (доступен без входа)
│   │   ├── Routes.kt                   # маршруты навигации + правила доступа по ролям (homeFor/isAllowed)
│   │   ├── DriverScreen.kt             # КАБИНЕТ ВОДИТЕЛЯ: карточки «Водитель»/«Машина» сверху, крупная заявка + «Взять в работу» / «Выполнено»
│   │   ├── DispatcherScreen.kt         # КАБИНЕТ ДИСПЕТЧЕРА: список заявок с фильтрами, создание
│   │   ├── CreateOrderScreen.kt        # постановка заявки: выбор корпуса (куда отправить водителя) + тип + электролизёр на схеме
│   │   ├── OrderScreen.kt              # карточка заявки (детали, ход исполнения)
│   │   ├── SchemeScreen.kt             # схема корпуса: выбор корпуса, весь корпус целиком с прокруткой, две линии электролизёров, проходы (проходимые/нет), центральная дорога, дороги вдоль стен, стены с единственным входом (Canvas)
│   │   ├── StatisticScreen.kt          # статистика наработки (моточасы)
│   │   └── GatesScreen.kt              # дистанционное открытие/закрытие ворот
│   ├── ui/
│   │   ├── Common.kt                   # QwantTopBar, StatusChip, UrgencyChip («светофор»), SectionCard, BuildingPicker (выбор корпуса), equipmentTypeTitle, …
│   │   ├── HallScheme.kt               # Canvas-отрисовка схемы; прокрутка, если схема шире экрана
│   │   ├── SchemeLayout.kt             # чистая геометрия корпуса (электролизёры, дороги, вход, масштаб на экране) + тесты
│   │   ├── SchemeTap.kt                # попадание пальцем по электролизёрам (зона касания ≥ 48 dp, «прилипание» к ближайшему) + тесты
│   │   ├── OrderCard.kt                # общая карточка заявки
│   │   ├── Format.kt                   # форматирование моточасов/времени/длительности
│   │   └── theme/                      # Color.kt (индустриальная палитра «графит+расплав»), Type.kt, Theme.kt
│   │   └── (ViewModel-и: XxxViewModel.kt рядом с экранами, MVVM, StateFlow)
│   └── res/
│       ├── drawable/ic_electrolysis_logo.xml  # фирменный логотип (электролизёр)
│       └── values/strings.xml          # ВСЕ строки UI — русские, хардкода в composable нет
```

**Вход и роли.** Стартовый маршрут — `auth`, если сессии нет, иначе кабинет роли
(`Routes.startFor`). Роль определяется учётной записью на сервере; экраны
разграничены (`Routes.isAllowed`, в `MainActivity` — `guardedComposable`):
водитель видит только кабинет водителя, диспетчер — кабинет и постановку заявок;
общие экраны (схема/ворота/статистика) доступны обеим ролям. Выход — кнопка
«Выйти» в шапке (`SessionStore.clear` + сброс токена).

**Шаблонной заглушек нет:** `MainScreen`/`DriverSelectScreen` (выбор кабинета/водителя)
удалены — их заменил вход по логину. Экраны `CreateOrderScreen`, `OrderScreen`,
`StatisticScreen` реализованы; `SchemeScreen.kt` — вместо `DotDangerScreens.kt`,
`GatesScreen.kt` — вместо `DistanceScreen.kt`.

**Архитектура:** MVVM, один `QwantApi` (без DI), навигация — `navigation-compose`.
Каждый экран — `XxxScreen` + `XxxViewModel` (`StateFlow<UiState>`), загрузка через
`viewModelScope`; кабинеты водителя/диспетчера перечитывают данные каждые 10 с,
т.к. сервер считает «светофор» и время исполнения на каждый запрос.

**Тесты:**
- Unit (`app/src/test/`): `AuthViewModelTest` (6) — вход, ошибки, валидация;
  `DeveloperViewModelTest` (5) — проверка связи и сохранение адреса сервера;
  `RoutesTest` (11) — старт по роли, разграничение экранов, доступ к экрану разработчика;
  `SchemeViewModelTest` (5) — загрузка корпусов, выбор корпуса, кэш схем и ворота;
  `CreateOrderViewModelTest` (4) — выбор корпуса (куда отправить водителя),
  загрузка схемы корпуса и постановка заявки;
  `DriverViewModelTest` (2) — техника водителя (карточка «Машина») и теги отклонений;
  `SchemeLayoutTest` (33) — геометрия схемы (две линии, центральная дорога, проезды)
  и масштаб на экране (ячейка не мельче `MIN_CELL_DP` = 50 dp ≈ 100 px);
  `SchemeTapTest` (7) — увеличенные зоны касания и «прилипание» к ближайшему
  электролизёру (пальцем по мелкой ячейке иначе не попасть);
  `ExampleUnitTest` (шаблон). Всего 74 теста.
  Запуск: `./gradlew test` (нужен `kotlinx-coroutines-test`).
- Инструментальные (`app/src/androidTest/`): `ThemeDesignTest` (3) — брендовые цвета
  «графит + расплав» и типографика планшета; `AuthScreenTest` (6) — поля, кнопка,
  ошибки, успешный вход, переход к экрану разработчика; `CabinetRoleTest` (2) — у водителя нет экранов диспетчера
  и наоборот; `ExampleInstrumentedTest` (шаблон). Запуск: `./gradlew connectedAndroidTest`
  (нужен эмулятор/устройство).
- Важно: **имена методов в androidTest — без пробелов** (бэктики со словами дают
  синтетические классы с пробелами, R8 отклоняет их для minSdk 24). В unit-тестах
  пробелы допустимы (не дексируются).

**Чего нет:** Room/локальной БД, DI, Coil, CI, настроенных линтеров/форматтеров
(ktlint/detekt/spotless отсутствуют), `values-ru` (основной `values/` уже русскоязычный).

**Известные «мелочи»:**
- Адрес сервера: дефолт `http://10.0.2.2:8080` задан в `data/ServerConfig.kt`
  и **настраивается в приложении** (служебный экран **«Для разработчика»**,
  ссылка внизу экрана входа — доступен без авторизации),
  хранится в SharedPreferences — без пересборки APK. `QwantApi.BASE_URL`
  читается из `ServerConfig` на каждый запрос.
- Сервер работает по HTTP, поэтому в манифесте `usesCleartextTraffic="true"` (только dev!).
- В корпусе порт 8080 может быть занят другим процессом — сервер поднимайте с `PORT=8081`
  и укажите этот порт в адресе сервера на экране входа.
- `server/build/` исторически закоммичен в git (артефакты сборки) — новые артефакты
  по-прежнему не стоит добавлять осознанно.

## 6. Рекомендации по разработке

- **Язык интерфейса — русский.** Все строки — в `res/values/strings.xml` (и, при
  необходимости, `values-ru/strings.xml`), не хардкодить в composable.
- **Compose + Material 3**, один `:app`-модуль. Экраны складывать в `com.example.qwant.screens`.
- **Именование экранов:** `*Screen.kt` (как в заглушках). Публичная точка входа
  экрана — `@Composable fun XxxScreen(...)`.
- **Состояние:** для новых фич добавляйте ViewModel (`lifecycle-viewmodel-compose`)
  и храните UI-state в `StateFlow`/`mutableStateOf`. MVVM уже внедрён (экраны
  реализованы как `XxxScreen` + `XxxViewModel`) — следуйте этому шаблону, чтобы
  соответствовать критерию «рациональность».
- **Сеть/сервер:** выбран и согласован стек — **Ktor Client + kotlinx-serialization**
  (`QwantApi.kt`, `BASE_URL`). Новые запросы добавляйте туда, а не в composable.
  Не забудьте про `INTERNET` в манифесте.
- **Авторизация:** экран входа — единственная точка получения токена; кладите сессию
  через `SessionStore.save(...)`, а токен — в `QwantApi.authToken`. Защищённый запрос
  по роли добавляйте на сервер (`Main.kt`) **и** отражайте в `Routes.isAllowed` —
  клиентский guard дублирует серверные проверки, но не заменяет их.
- **Ключевой UX-критерий кейса:** минимум действий. Главный экран водителя —
  крупная заявка + одна кнопка **«Взять в работу»**, затем **«Выполнено»**;
  один тап на быстрый тег отклонения. Не усложняйте.
- **Схема корпуса:** сначала выбор **корпуса** (`GET /api/buildings`, по умолчанию
  корпус №4; в образцовой БД корпуса №4/№3/№2/№1), затем схема выбранного
  корпуса; экран «Схема» показывает **весь корпус целиком** (все линии и
  электролизёры) и **прокручивается по горизонтали**, если схема шире экрана
  (на телефоне не уменьшается), заявка привязывается к электролизёру на схеме;
  электролизёры — **две линии по обе стороны центральной дороги** корпуса,
  стоят **по отдельности** (каждый в своей рамке, между соседями — проход для
  техники), по центру — **широкая дорога разворота**, вдоль
  стен — **дороги для выезда к воротам**, стены с одним входом (слева или
  справа); нужны опасные зоны/тупики и (доп.) дистанционное открытие ворот.
- **Попадание пальцем по электролизёру.** Ячейка на схеме не мельче
  `HallLayout.MIN_CELL_DP` (50 dp ≈ 100 px на плотности 320), а попадание считается не
  по контуру, а по **увеличенной зоне касания** (≥ 48 dp, `SchemeTap.kt`): при
  нескольких кандидатах выбирается **ближайший** электролизёр (при равном
  расстоянии — с ближайшим центром). Покрыто unit-тестами `SchemeTapTest`.
- **СДЕЛАНО (2026-10-17):** `SchemeTap.kt` + `SchemeTapTest` (7) — попадание
  пальцем вне контура ячейки выбирает ближайший электролизёр; инструментальные
  тесты прогнаны на устройстве (`am instrument` → `OK (11 tests)`; Gradle-таск
  `connectedAndroidTest` на телефоне MIUI падает на установке APK —
  `INSTALL_FAILED_USER_RESTRICTED`). Ячейка электролизёра увеличена до
  `MIN_CELL_DP` = 50 dp (≈100 px на плотности 320), а проезд техники между
  соседями сужен до `BLOCK_GAP` = 0.7 ячейки (≈70 px): при
  `BLOCK_SIZE = 1` между каждой парой электролизёров — проезд уже самого
  электролизёра, но по нему встаёт МРГ/МПК. Поэтому широкий корпус
  (150 электролизёров → 75 в ряду, ≈6400 dp) прокручивается по горизонтали.
- **Дороги вдоль стен** — узкие служебные полосы: `SIDE_LANE` = 0.5 ячейки
  (≈50 px, вдоль боковых стен) и `TURN_LANE` = 1.0 ячейки (≈100 px, вдоль
  торцевых стен) — ничего больше в схеме не менялось; центральная дорога
  разворота (`AISLE_H` = 2.0 → 200 px) остаётся самой широкой.
- **Вход в приложение — один раз.** Сессия хранится в `State` и читается
  *внутри* экранов (`MainActivity.guardedComposable`), а граф навигации
  строится один раз в `remember(navController) { createGraph(...) }`: иначе
  сразу после входа проверка роли срабатывала по устаревшему (пустому)
  значению и возвращала пользователя на экран входа — приходилось входить
  дважды.
- **Клавиатура.** Прокручиваемые экраны с полями ввода (вход, постановка
  заявки) применяют `Modifier.imePadding()`: при edge-to-edge окно само не
  уменьшается, и без этого содержимое «проваливается» под клавиатуру
  (в манифесте уже стоит `windowSoftInputMode="adjustResize"`).
- **Экран «Схема корпуса»** больше не печатает подпись «Показан весь корпус…»
  (строка `scheme_full_note` удалена).
- **Статистика:** наработка в **моточасах**; для МРГ — «светофор» срочности
  (зелёный → оранжевый 10 мин → красный 15 мин).
- **Не удаляйте** фото-ТЗ и `AGENTS.md`. `local.properties`, `build/`, `.gradle/`,
  `.kotlin/`, `.idea/` — генерируемые, не коммитить.
- **Проверяйте сборку** после значимых правок: `./gradlew assembleDebug` (и `./gradlew test`).
- **Сервер - для базы данных используй sqlite3 для образной базы данных**
- **Электролизеры расположены двумя параллельными линиями по обе стороны центральной дороги, поделенные пополам. их может быть как 100, как и 150**
