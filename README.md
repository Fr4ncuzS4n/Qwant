# Qwant — мобильное приложение для водителей дизельной техники

Клиент-серверное решение по кейсу **«Мобильное приложение для водителей дизельной
техники»** (электролизное производство алюминия).

Приложение автоматизирует работу водителей с заявками на обработку электролизёров
и минимизирует число действий водителя — **всего два тапа**:
**«Взять в работу»** и **«Выполнено»**. Диспетчер ставит заявки, контролирует
исполнение и видит «светофор» срочности заявок по подсыпке.

## 1. Что умеет приложение

**Для водителя** (`DRIVER`):
- личный кабинет с крупным уведомлением о новой заявке;
- **действие №1** — «Взять в работу» (статус `NEW → ACCEPTED`, исполнитель
  определяется сервером по токену);
- **действие №2** — «Выполнено» (`ACCEPTED → DONE`), при необходимости с **быстрым
  тегом отклонения** (без ручного ввода) и наработкой в моточасах.

**Для диспетчера** (`DISPATCHER`):
- кабинет со списком заявок и фильтрами (все / новые / в работе / выполненные /
  ремонт);
- **постановка заявки** из кабины: тип + выбор электролизёра **на схеме корпуса**;
- контроль времени исполнения и индикация «светофора».

**Общее для обеих ролей:**
- **схема корпуса** — электролизёры (две линии по обе стороны центральной дороги),
  проезды техники, дороги вдоль стен, единственный вход (ворота) в стене,
  **опасные зоны и тупики**;
- **дистанционное открытие/закрытие ворот**;
- **статистика наработки** техники в **моточасах** и сводка по заявкам.

**Индикация срочности («светофор») — только для заявок `PODSYPKA` в статусе
`ACCEPTED`:**
- 🟢 зелёный — сразу после принятия;
- 🟠 оранжевый — через **10 минут**;
- 🔴 красный — через **15 минут**.

## 2. Архитектура

```
┌────────────────────────────┐        HTTP / JSON         ┌──────────────────────────┐
│  Android-клиент (:app)      │  ───────────────────────►  │  Сервер (server/)        │
│  Kotlin + Jetpack Compose   │  X-Auth-Token: <token>     │  Ktor + sqlite3          │
│  MVVM, Ktor Client          │  ◄───────────────────────  │  REST API /api/*         │
└────────────────────────────┘                            └──────────────────────────┘
```

- **Клиент** ничего не считает сам про время: «светофор», `elapsedMinutes` и
  агрегированную статистику вычисляет сервер на каждый запрос, поэтому кабинеты
  периодически опрашивают API (каждые 10 с).
- **Авторизация**: клиент входит по логину/паролю, получает токен и передаёт его
  в заголовке `X-Auth-Token`. Роль хранится в учётной записи на сервере.
- **Разграничение прав** продублировано: клиентским guard'ом по ролям
  (`Routes.isAllowed`) **и** серверными проверками в `Main.kt`. Клиентский guard
  не заменяет серверные проверки.

## 5. Быстрый старт

### Требования

- **JDK 21+** (для сервера) и **JDK 25** для Gradle-демона Android-сборки
  (подтянется автоматически через foojay-resolver);
- **Android SDK** (`local.properties`: `sdk.dir=...`, в git не добавляется);
- интернет при первой сборке (скачивание зависимостей).

### 1) Запустить сервер

```bash
# из корня репозитория
./gradlew -p server run
```

Сервер поднимется на **`http://0.0.0.0:8080`**. Для Android-эмулятора хост-машина
доступна как **`http://10.0.2.2:8080`** (это адрес по умолчанию в приложении).

Проверка:

```bash
curl http://localhost:8080/api/health
# {"status":"ok","service":"qwant-server","time":"..."}
```

### 2) Собрать и запустить приложение

```bash
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Установить на устройство/эмулятор:

```bash
./gradlew installDebug
```

Приложение стартует с **экрана входа**. Для физического планшета измените адрес
сервера на служебном экране **«Для разработчика»** (ссылка внизу экрана входа) на
`http://IP-компьютера:порт` — пересборка APK не нужна.

### Демо-доступ

| Логин | Пароль | Роль |
|---|---|---|
| `dispatcher` | `1234` | Диспетчер |
| `ivanov` | `1234` | Водитель (Иванов А.) |

| `sidorov` | `1234` | Водитель (Сидоров В.) |


## 6. Серверная часть (`server/`)

Отдельный Gradle-проект (`rootProject.name = "qwant-server"`), запускается
независимо от Android-сборки.

### 6.1. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `QWANT_DB` | `:memory:` | Путь к файлу БД sqlite3. По умолчанию — **образная база в памяти**, заполняется при старте. Укажите путь, чтобы сохранять данные между запусками. |
| `QWANT_ELECTROLYZERS` | `150` | Число электролизёров в **каждом корпусе** (`100` или `150`) |

Пример с файловой БД и 100 электролизёрами:

```bash
QWANT_DB=./qwant.db QWANT_ELECTROLYZERS=100 ./gradlew -p server run
```

Если порт занят:

```bash
PORT=8081 ./gradlew -p server run
```

### 6.2. Модель данных (sqlite3)

| Таблица | Назначение |
|---|---|
| `equipment` | дизельная техника (`MRG` — раздачи глинозёма, `MPK` — пробойки корки), наработка в моточасах |
| `drivers` | водители, каждый закреплён за техникой |
| `electrolyzers` | электролизёры: `building`, `row`, `position`, `half` (`A`/`B`), `series`, `status` |
| `zones` | опасные зоны (`DANGER`) и тупики (`DEAD_END`), координаты 0..1, у каждого корпуса свои |
| `gates` | ворота корпуса (дистанционное открытие). `x < 0.5` → вход слева, иначе справа |
| `deviation_tags` | быстрые теги отклонений (выбор без ввода текста) |
| `orders` | заявки |
| `users` | учётные записи (`login`, `password_hash`, `salt`, `role`, `driver_id`) |
| `sessions` | активные токены авторизации (`token`, `user_id`, `created_at`) |

Пароли хранятся как **SHA-256(salt + password)** в hex (соль — UUID), в открытом
виде не сохраняются.

### 6.3. Корпуса и раскладка электролизёров

В образцовой базе — **четыре корпуса** (`GET /api/buildings`), у всех одинаковая
раскладка и различаются только вход, зоны и ворота.

| Корпус | Всего | Линии | В линии | Половина | Вход |
|---|---|---|---|---|---|
| **№4** (по умолчанию) | 150 | 2 | 75 | 37 | слева |
| №3 | 150 | 2 | 75 | 37 | справа |
| №2 | 150 | 2 | 75 | 37 | справа |
| №1 | 150 | 2 | 75 | 37 | справа |

Правила раскладки: `rows = 2` — **две линии по обе стороны центральной дороги**
корпуса; `perRow = count / 2` (электролизёров в линии); `halfSize = perRow / 2`
(линия делится пополам: половина `A` — первая, `B` — вторая). Нумерация в каждом
корпусе начинается с 1. Число электролизёров задаёт `QWANT_ELECTROLYZERS`.

### 6.4. Бизнес-правила

- **Авторизация по логину/паролю.** `POST /api/auth/login` выдаёт токен; далее
  запросы передают `X-Auth-Token`. Роль (`DISPATCHER`/`DRIVER`) хранится в учётке.
- **Разграничение ролей:**
  - `POST /api/orders` — **только диспетчер** (иначе `403`);
  - `/accept` и `/complete` — **только водитель**, `driverId` берётся из токена;
  - ворота `open`/`close` — любой авторизованный (без токена `401`);
  - `GET`-эндпоинты чтения — открыты.
- **Два действия водителя:** `/accept` → `/complete`.
- **Светофор срочности** — только `PODSYPKA` в статусе `ACCEPTED`: 🟢 < 10 мин,
  🟠 10–14 мин, 🔴 ≥ 15 мин. Поле `urgency` в JSON заявки.
- **Моточасы:** при `/complete` с `motohoursDelta > 0` наработка начисляется технике
  исполнителя.
- **Заявка на ремонт** — тип `REMONT`, `isRepair = true`.

### 6.5. Запуск вручную (`curl`)

```bash
# вход диспетчера -> токен
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"dispatcher","password":"1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# новая заявка
curl -X POST localhost:8080/api/orders \
  -H "X-Auth-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"type":"PODSYPKA","electrolyzerId":125}'

# вход водителя -> он же становится исполнителем
DTOKEN=$(curl -s -X POST localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"ivanov","password":"1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

curl -X POST localhost:8080/api/orders/1/accept -H "X-Auth-Token: $DTOKEN"
curl -X POST localhost:8080/api/orders/1/complete -H "X-Auth-Token: $DTOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"deviationTagId":1,"comment":"Засор лотка","motohoursDelta":1.5}'

curl -X POST localhost:8080/api/gates/1/open -H "X-Auth-Token: $TOKEN"
curl localhost:8080/api/stats
```

## 7. REST API

Базовый префикс — `/api`. Тело запросов/ответов — JSON. Защищённые эндпоинты
требуют заголовок **`X-Auth-Token: <token>`**.

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| GET | `/api/health` | — | Проверка доступности |
| POST | `/api/auth/login` | — | Вход `{ "login", "password" }` → `{ token, user }` |
| POST | `/api/auth/logout` | вход | Выход (аннулирует токен) |
| GET | `/api/auth/me` | вход | Текущий пользователь по токену |
| GET | `/api/config` | — | Параметры схемы (корпус по умолчанию, ряды, число электролизёров, список корпусов) |
| GET | `/api/equipment` | — | Список техники с моточасами |
| GET | `/api/equipment/{id}` | — | Техника по id |
| POST | `/api/equipment/{id}/motohours` | диспетчер | Начислить моточасы `{ "delta": 2.5 }` |
| GET | `/api/drivers` | — | Водители с закреплённой техникой |
| GET | `/api/buildings` | — | Корпуса цеха (идентификатор, название, раскладка) |
| GET | `/api/electrolyzers?building=4` | — | Электролизёры (всех корпусов или указанного) |
| GET | `/api/scheme?building=4` | — | Схема корпуса: электролизёры + зоны + ворота (`404`, если корпуса нет) |
| GET | `/api/gates` | — | Ворота |
| POST | `/api/gates/{id}/open` | вход | **Дистанционно открыть** ворота |
| POST | `/api/gates/{id}/close` | вход | Закрыть ворота |
| GET | `/api/tags` | — | Быстрые теги отклонений |
| GET | `/api/stats` | — | Статистика наработки (моточасы, счётчики заявок) |
| GET | `/api/orders?status=&driverId=&isRepair=` | — | Список заявок с фильтрами |
| GET | `/api/orders/{id}` | — | Заявка по id |
| POST | `/api/orders` | диспетчер | Создать заявку |
| POST | `/api/orders/{id}/accept` | водитель | **«Взять в работу»** (исполнитель — владелец токена) |
| POST | `/api/orders/{id}/complete` | водитель | **«Выполнено»** `{ deviationTagId, comment, motohoursDelta }` |

### Пример ответа по заявке

```json
{
  "id": 2,
  "type": "PODSYPKA",
  "status": "ACCEPTED",
  "electrolyzerNumber": 42,
  "building": "4",
  "row": 2, "position": 12, "half": "A",
  "driverId": 1, "driverName": "Иванов А.",
  "elapsedMinutes": 12,
  "urgency": "ORANGE",
  "createdAt": "...", "acceptedAt": "...", "completedAt": null
}
```

## 8. Android-приложение (`app/`)

### 8.1. Экраны и навигация

Навигация — `navigation-compose`. Стартовый маршрут — `auth`, если сессии нет,
иначе кабинет роли (`Routes.startFor`). Каждый защищённый маршрут обёрнут в
`guardedComposable`: при отсутствии доступа пользователь перенаправляется на свой
домашний экран.

| Маршрут (`Routes`) | Экран | Роль |
|---|---|---|
| `auth` | `AuthScreen` — вход по логину/паролю | все |
| `developer` | `DeveloperScreen` — «Для разработчика»: адрес сервера и проверка связи | все (в т.ч. без входа) |
| `driver` | `DriverScreen` — кабинет водителя | только `DRIVER` |
| `dispatcher` | `DispatcherScreen` — кабинет диспетчера | только `DISPATCHER` |
| `create_order` | `CreateOrderScreen` — постановка заявки (выбор корпуса, куда отправить водителя) | только `DISPATCHER` |
| `order/{orderId}` | `OrderScreen` — карточка заявки | обе |
| `scheme` | `SchemeScreen` — схема корпуса | обе |
| `gates` | `GatesScreen` — открытие/закрытие ворот | обе |
| `stats` | `StatisticScreen` — статистика наработки | обе |

Выход — кнопка «Выйти» в шапке (`SessionStore.clear` + сброс токена).

### 8.2. Слои

```
ui-экраны (screens/XxxScreen.kt)
        │ collectAsStateWithLifecycle
        ▼
ViewModel (screens/XxxViewModel.kt)   StateFlow<UiState>
        │ viewModelScope
        ▼
QwantApi (data/QwantApi.kt)           единый Ktor-клиент, без DI
        │
        ▼
Сервер (/api/*)
```

- **MVVM**: каждый экран — `XxxScreen` + `XxxViewModel` с `StateFlow<UiState>`.
- **`QwantApi`** — тонкая обёртка над Ktor, единственная точка сетевых запросов.
  Токен подставляется в `defaultRequest` через `QwantApi.authToken`.
- **`ServerConfig`** — адрес сервера (по умолчанию `http://10.0.2.2:8080`),
  настраивается на экране входа, хранится в SharedPreferences и читается
  `QwantApi.BASE_URL` **на каждый запрос** (без пересборки APK).
- **`SessionStore`** — токен и данные учётной записи в SharedPreferences.
- Кабинеты водителя и диспетчера **перечитывают данные каждые 10 с**
  (`LaunchedEffect` + `delay(10_000)`), т.к. сервер считает «светофор»
  и время исполнения на каждый запрос.

### 8.3. Ключевой сценарий водителя

1. Наверху кабинета — акцентные карточки **«Водитель»** (ФИО, логин, роль)
   и **«Машина»** (техника водителя: тип МРГ/МПК, модель и наработка в моточасах),
   затем список заявок.
2. Крупная карточка новой заявки с кнопкой **«Взять в работу»**.
3. После принятия заявка переходит в раздел «Моя заявка» с кнопкой **«Выполнено»**.
4. По нажатию «Выполнено» открывается нижняя панель: поле моточасов и список
   **быстрых тегов отклонений** (один тап) либо кнопка «Выполнено без отклонений».

Постановка заявки диспетчером (`CreateOrderScreen`): сначала выбирается **корпус**,
в который отправляется водитель (чипы «Корпус N · количество электролизёров»,
как на экране «Схема»), затем тип заявки и электролизёр на схеме выбранного
корпуса. Смена корпуса перезагружает схему и сбрасывает выбранный электролизёр.

## 9. Схема корпуса

Геометрия вынесена в **чистый (независимый от Android/Compose) класс**
`ui/SchemeLayout.kt` (`HallLayout`) и покрыта unit-тестами.

Устройство корпуса:
- электролизёры стоят **двумя линиями** по обе стороны **центральной дороги**,
  **по отдельности** (каждый в своей рамке), между соседями — **проезд техники**
  (`BLOCK_GAP`, уже самого электролизёра);
- линия делится пополам (половины `A`/`B`);
- по центру — широкая **центральная дорога** (`AISLE_H`) для разворота техники
  к электролизёрам; по высоте совпадает с положением входа;
- вдоль боковых и торцевых стен — **дороги** для выезда к воротам;
- в корпусе **один вход** (`gates`, слева или справа) — стена с воротами
  разомкнута;
- отмечены **опасные зоны** (`DANGER`) и **тупики** (`DEAD_END`).

Особенности отображения:
- экран «Схема» показывает **весь корпус целиком** (все линии и электролизёры)
  и **прокручивается по горизонтали**, если схема шире экрана;
- ячейка электролизёра — **не мельче `MIN_CELL_DP` = 50 dp** (≈ 100 px на
  плотности 320);
- **попадание пальцем** считается не по контуру, а по **увеличенной зоне касания**
  (≥ `SCHEME_MIN_TOUCH_DP` = 48 dp, `ui/SchemeTap.kt`): при нескольких кандидатах
  выбирается **ближайший** электролизёр (при равном расстоянии — с ближайшим
  центром). Покрыто тестами `SchemeTapTest`.
- схемы корпусов **кэшируются** во ViewModel — переключение между уже открытыми
  корпусами мгновенное.

## 11. Дизайн и локализация

- **Тема** — фирменная индустриальная палитра **«графит / сталь / алюминий +
  расплав электролита»** (см. `ui/theme/Color.kt`): тёмный графит корпусов,
  серебристо-серый алюминий, оранжево-медный жар расплава (~960 °C).
- **Сигнальные цвета** «светофора» — отдельные (зелёный / оранжевый / красный),
  не смешиваются с фирменными акцентами.
- **Язык интерфейса — русский.** Все строки UI — в `res/values/strings.xml`,
  хардкода строк в composable нет. Логотип — `res/drawable/ic_electrolysis_logo.xml`.
- Тема задаётся в `ui/theme/Theme.kt` (`QwantTheme`), типографика — в `Type.kt`.

## 12. Частые проблемы

**Сервер не запускается — порт 8080 занят.**
Запустите на другом порту и укажите его в приложении:
```bash
PORT=8081 ./gradlew -p server run
```
на экране **«Для разработчика»** (ссылка внизу экрана входа) →
`http://10.0.2.2:8081` (эмулятор) или `http://IP-компьютера:8081` (физический планшет).

**Приложение не видит сервер с реального планшета.**
Проверьте, что устройство и компьютер в одной сети, используйте IP компьютера
(не `10.0.2.2` — это только для эмулятора) и разрешите входящие соединения на
выбранный порт.

**HTTP-трафик.** Сервер работает по HTTP, поэтому в манифесте включён
`usesCleartextTraffic="true"` — только для dev-среды.

**Данные не сохраняются между запусками сервера.**
По умолчанию используется образная БД в памяти. Укажите файл:
`QWANT_DB=./qwant.db ./gradlew -p server run`.

**`local.properties` отсутствует.**
Создайте файл с `sdk.dir=/путь/к/Android/Sdk` (в git не коммитится).

### Правила при доработках

- UI-текст — русский, только в `strings.xml`.
- Состояние — во ViewModel (`StateFlow`), не в composable.
- Сетевые запросы — в `QwantApi`, не в composable.
- Разграничение по ролям — и на сервере (`Main.kt`), и в `Routes.isAllowed`.
- При добавлении маршрутов обновляйте `server/README.md` и `AGENTS.md`.
- После значимых правок: `./gradlew assembleDebug` и `./gradlew test`.
- Не удаляйте фото-спецификацию кейса и `AGENTS.md`.
- `local.properties`, `build/`, `.gradle/`, `.kotlin/`, `.idea/` — генерируемые,
  не коммитить.
